# Псевдоречь диалогов

Голос встроен в существующую цепочку `NpcVisit → DialogPhrases → DialogCanvas → TypewriterText`. Текст, локализация и управление через E работают как раньше. Отдельная система диалогов не создаётся.

Мужчина без лица в FastFood использует профиль `Assets/Audio/Voices/FacelessDarkRadio.asset`: 13 фрагментов `03_Dark_Radio.wav` по 0.285–1.26 с. Разрезы выбраны по низкоэнергетическим промежуткам записи, связные отрезки сохранены; на краях применено сглаживание 8 мс. Длинные паузы удалены, один общий коэффициент усиления сохраняет различия громкости фрагментов. Оригинал во внешней базе не менялся. Точки нарезки и SHA-256 записаны в `Assets/Audio/Voices/FacelessDarkRadio/preparation.json`; воспроизвести подготовку можно через `AgentScripts/PrepareDarkRadioVoice.py` (существующие файлы не перезаписывает).

## Настройка в Inspector

Выберите `FacelessDarkRadio.asset` в Project:

| Поле | Текущее значение | Назначение |
| --- | --- | --- |
| Clips | 13 WAV | Набор речевых фрагментов; пустые и повторные ссылки игнорируются |
| Volume | 0.18 | Громкость голоса, дополнительно подчиняется общей громкости игры |
| Fragments Per Second | 3 | Максимальная частота начала фрагментов; меньшие значения делают речь реже |
| Pause Range | 0.08–0.18 с | Случайная пауза после завершения фрагмента |
| Pitch Range | 0.94–1.04 | Случайная высота голоса; 1 соответствует исходнику, X = Y фиксирует высоту |

Частота задаёт верхний предел: новый фрагмент ждёт завершения предыдущего и короткой паузы. Она не ускоряет текущую запись. Темп текста остаётся в `TypewriterText / Characters Per Second`, паузы пунктуации — в `Punctuation Delay`.

Для нового персонажа создайте профиль через **Create → DREAMS → Dialogue Voice Profile**, заполните `Clips` и назначьте его в **NpcVisit / Voice Profile** у нужного персонажа. В FastFood профиль мужчины без лица назначен на `TillTrigger / NpcVisit`; профиль администратора — на `AdminWakeUpVisit` и `AdminBriefing`. Для отдельных диалоговых окон можно задать голос по умолчанию в **DialogCanvas / Voice Profile**. Явно переданный голос персонажа имеет приоритет. Пустой профиль окна и персонажа означает тихую печать.

Администратор использует `Assets/Audio/Voices/AdminAbyssalWarden.asset`: 21 фрагмент по 0.460–0.885 с из внешнего `admin_voice/12_Abyssal_Warden.wav`. Настройки: `Volume = 0.15` (уровень согласован с Dark Radio по средней энергии), `Fragments Per Second = 3`, `Pause Range = 0.09–0.20 с`, `Pitch Range = 0.97–1.03`. Голос включён при пробуждении и инструктаже у кассы; его окно `Dialog_Subtitles_Admin` также имеет этот профиль по умолчанию. Подготовка — `AgentScripts/PrepareAdminVoice.py`, исходник сохранён, точки нарезки/SHA-256 — в `Assets/Audio/Voices/AdminAbyssalWarden/preparation.json`. Узкое назначение выполняет `ConfigureDialogueVoices.ApplyAdmin`: оно сохраняет сцену и не перенастраивает голос мужчины без лица.

`TypewriterText / Voice Audio` ссылается на отдельный дочерний `VoiceAudio`, 2D, без Loop и Play On Awake. Прежняя ссылка `_typingAudio` мигрирует через `FormerlySerializedAs`; старый клип печати снят с источников общего CAMERA.prefab и двух местных окон FastFood. Остальные сцены наследуют тихий источник из префаба. Старый аудиофайл печати оставлен как неиспользуемый ресурс.

## Поведение и проверки

Фрагменты запускаются во время появления букв и цифр. Пунктуация не создаёт новых звуков. Используется перемешиваемый набор, последние два варианта избегаются и на границе набора. При выборе учитывается оставшееся время печати и pitch: слишком длинный фрагмент не начинается перед последней буквой. Если в наборе остались только длинные варианты, короткие подходящие варианты пополняются заново, чтобы последующие короткие реплики не замолчали. Один AudioSource воспроизводит один фрагмент; наложений нет. Пауза останавливает текущий фрагмент и продолжает с прежнего места; при `Use Unscaled Time` голос следует выбранному режиму печати текста.

Для устранения обрывов и щелчков при завершении/пропуске/закрытии/смене реплики используется `DialogueVoiceEnvelope`, автоматически добавляемый на отдельный `VoiceAudio`. Он обрабатывает звук в аудиопотоке через `OnAudioFilterRead`: вход 8 мс, затухание 45 мс, затем остановка уже при нулевом усилении с учётом буфера аудиоустройства. Новые фрагменты прекращаются сразу; короткое затухание завершает текущий без скачка сигнала. При смене реплики новый голос ждёт затухания старого. Сами WAV и профили не менялись. Отключение/уничтожение объекта источника по-прежнему останавливает его полностью; уже приостановленный голос при пропуске сбрасывается без возобновления.

`AgentScripts/ConfigureDialogueVoices.cs` настраивает ресурсы, общий префаб и открытую FastFood, предварительно сохраняя копию сцены. Повторно не запускайте для обычной настройки: он вернёт профиль к указанным выше значениям. Старый `ConfigureDialogueTypingAudio.cs` относится к прежней реализации и больше не применяется.

Локальные отчёты в `Logs/DialogueVoice/`: 31 проверка в Play Mode (реальный NpcVisit, аудиосигнал, E, завершение, закрытие/отключение, пауза, случайность и отсутствие наложений, громкость/частота/pitch, RU/EN), плюс загрузка настоящей NightField со сбросом прежнего голоса и проверкой отсутствия звука печати.

После подключения администратора отдельно пройдены 24 проверки обоих настоящих NpcVisit, первых/вторых реплик, аудиосигнала, E, закрытия, паузы/продолжения, случайных фрагментов без наложений и разделения голосов. Отчёт — `Logs/AdminVoice/results.txt`. Старое ожидание «администратор без голоса» в прежней проверке `Logs/DialogueVoice/VerifyDialogueVoice.cs` устарело.

Исправление щелчков: `Logs/VoiceClickFix/`, 36 проверок Play Mode для обоих голосов: реальное изменение gain в аудиопотоке, затухание перед остановкой, смена реплики, естественное завершение подходящих по длительности фрагментов, короткие реплики, пауза/пропуск. Для ненулевого тестового сигнала проверена непрерывность аудиосэмплов и одинаковая огибающая каналов. Старые ожидания мгновенного `!AudioSource.isPlaying` после E/закрытия устарели: источник может оставаться активным на время короткого затухания и обработки буфера, новых фрагментов при этом нет.
